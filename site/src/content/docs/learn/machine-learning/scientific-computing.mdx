## Foundations

Scientific ML combines a prediction target, a representation, an objective, an
optimization procedure, and an uncertainty statement. Geometric and graph
methods encode useful inductive biases, but no architecture repairs a mismatched
label or a contaminated split. [DGL-LifeSci](https://github.com/awslabs/dgl-lifesci)
and [PyTorch Geometric](https://github.com/pyg-team/pytorch_geometric) expose
common graph-learning building blocks.

## Practical workflow

Start with a fixed data table, a train-only preprocessing pipeline, and a
baseline such as regularized linear regression, a random forest, or a simple
fingerprint model. Record seed handling, checkpoint selection, and the exact
inference inputs. Only add geometric complexity after the cheap baseline and
data contract are stable.

## Evaluation

Report the independent unit, not only the number of rows or optimization steps.
Do not choose a model on the test set. Compare models under the same split,
budget, and selection rule; otherwise a larger score may reflect a protocol
difference rather than a method difference.

## Frontier and open questions

Foundation models and scientific recipe collections such as
[BioNeMo Recipes](https://github.com/NVIDIA-BioNeMo/bionemo-recipes) can reduce
implementation cost, but their transferred assumptions and asset terms must be
audited task by task.

## A bounded worked decision and independent task

After [records to a modelling table](/learn/data-governance/records-to-model-table/), connect a fitting call to its mathematical input. In the constructed [Ridge derivation](/learn/machine-learning/baseline-training-validation/), training pairs (0,1), (1,3), (2,5) with alpha 2 yield slope 1 and intercept 2. At feature 3 the prediction is 5. A scaler, feature mapping and coefficient vector are all part of the saved inference recipe; a checkpoint name alone does not define it.

A collaborator reloads the coefficients but fits a new scaler on the evaluation batch. Did they evaluate the same mapping? State the artifact needed to make the procedure inspectable.

<details data-worked-answer>
<summary>Check the reasoning after your attempt</summary>

No. Fitting the new scaler changes the input mapping even when coefficients are unchanged. Retain the training-fitted preprocessing state, representation settings, feature order, selected parameters and inference command. This checks computational identity, not whether the scientific endpoint was valid or whether the model generalizes.

</details>
