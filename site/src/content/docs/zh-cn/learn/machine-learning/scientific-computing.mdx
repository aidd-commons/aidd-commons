## 基础

科学 ML 结合预测目标、表示、目标函数、优化程序和不确定性陈述。几何和图方法编码有用的
归纳偏置，但没有任何架构能修复不匹配的标签或受污染的划分。
[DGL-LifeSci](https://github.com/awslabs/dgl-lifesci) 和
[PyTorch Geometric](https://github.com/pyg-team/pytorch_geometric) 提供常见的图学习构建模块。

## 实践工作流

从固定的数据表、仅在训练集上拟合的预处理流水线，以及正则化线性回归、随机森林或简单
指纹模型等基线开始。记录种子处理、检查点选择和确切的推理输入。只有在低成本基线和
数据契约稳定后，才加入几何复杂性。

## 评估

报告独立单位，而不仅是行数或优化步数。不要在测试集上选择模型。在相同的划分、预算和
选择规则下比较模型；否则，更高的分数可能反映的是协议差异而不是方法差异。

## 前沿与开放问题

基础模型和诸如 [BioNeMo Recipes](https://github.com/NVIDIA-BioNeMo/bionemo-recipes) 的
科学配方集合可以降低实现成本，但其迁移的假设和资产条款必须逐任务审查。

## 有边界的推演与独立任务

阅读[从记录到模型表](/zh-cn/learn/data-governance/records-to-model-table/)后，把拟合调用对应到数学输入。在构造的[Ridge 推导](/zh-cn/learn/machine-learning/baseline-training-validation/)中，训练点 (0,1)、(1,3)、(2,5) 在 alpha 2 时得到斜率 1、截距 2，特征为 3 时预测为 5。Scaler、特征映射与系数向量都是保存推断配方的一部分；checkpoint 名称本身不能定义它。

协作者重新加载系数，却在评估 batch 上拟合了新 scaler。他们评估的还是同一映射吗？指出使过程可检查所需的产物。

<details data-worked-answer>
<summary>完成后核对推理</summary>

不是。即使系数不变，重新拟合 scaler 也会改变输入映射。应保留仅训练集拟合的预处理状态、表示设置、特征顺序、选定参数与推断命令。这检验计算身份，不检验科学终点是否有效或模型是否泛化。
