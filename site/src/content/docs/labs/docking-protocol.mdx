## Before you run

**Mode: runnable inspection of committed declarations.** **No docking program is
run**, no structure is prepared, and the reported numbers are illustrative values
rather than results.

```bash
python labs/docking_protocol/inspect_protocol.py show
```

A docking score arrives as a number with units, which invites comparison with any
other number carrying those units. It is the output of seven declared choices.

## 1. Five components move the number, two move what it means

**Search, pose generation, scoring, rescoring and constraints** can each change
the reported number. A different amount of searching finds different poses, so the best score
found is a property of the search as much as of the ligand. A constraint removes
poses from consideration, so it changes which pose is best.

**Decoys and validation** change no score at all. They decide whether an
enrichment figure exists and whether the scores were ever checked to behave as
scores. That is exactly why they are the easiest two to leave out: a protocol
without them still produces a full column of numbers.

## 2. The cleanest incomparable pair

`p-baseline` and `p-rescored` differ in **exactly one component**. Same search,
same pose generation, same scoring function, same constraints, same decoys, same
validation. Same ligand, same structure.

One applies a second scoring function to the top pose.

| protocol | reported |
| --- | --- |
| `p-baseline` | **-8.2** |
| `p-rescored` | **-10.7** |

Both in kcal per mole. **Nothing about the ligand changed and the 2.5 gap is
entirely the protocol.** The second number came out of a different function, so
the two are not on one scale.

## 3. No pair in this set may be compared

The command works out every pair and names the components that block it:

- `p-baseline` against `p-rescored`: blocked by rescoring
- `p-baseline` against `p-constrained`: blocked by search and constraints
- `p-rescored` against `p-constrained`: blocked by search, rescoring and constraints

Shared units alone do not establish comparability. The lab's frozen rule refuses
to treat these different protocols as a controlled ligand-ranking comparison.
The protocol differences can still be compared. A search-effort difference does
not necessarily change the scoring function's scale.

## 4. What a protocol without validation cannot report

```bash
python labs/docking_protocol/inspect_protocol.py check
```

`p-constrained` declares no validation and no decoys. The lab records what it
therefore cannot report: a claim of validated pose or ranking quality, and an enrichment figure against
the declared decoy set under this protocol. This rule bounds the lab's reporting;
it does not claim that all enrichment calculations require the same decoy design.

Eleven checks run. A protocol that is not fully declared stops the run before any
comparison is attempted, because a comparison against an unstated protocol is not
a comparison.

## 5. Real-structure empirical docking over RCSB PDB EGFR co-crystals (`empirical-docking`)

Alongside the protocol-card comparison, `empirical-docking` and
`check-empirical-docking` execute a deterministic, offline real-structure scoring
audit over `3` RCSB PDB human EGFR kinase co-crystal complexes (`1M17`, `4HJO`,
`1XKK`) in `labs/docking_protocol/data/egfr_cocrystals.json`:

```bash
python labs/docking_protocol/inspect_protocol.py empirical-docking
python labs/docking_protocol/inspect_protocol.py check-empirical-docking
```

- **Redocking & rescoring scale shift (`1M17` / erlotinib `AQ4`, `157` pocket
  heavy atoms within `10` Å)**: across `28` candidate poses, the crystal pose
  (`pose_01_crystal`, RMSD `0.0` Å, Met793 backbone N distance `2.6991` Å, `0`
  heavy-atom clashes `< 2.4` Å) scores `-15.6194` under the empirical vdW +
  Met793 hydrogen-bond function and `-12.46` under vdW-only rescoring (a scale
  shift of `+3.1594` on the identical atomic coordinates). The top redocked
  non-crystal pose (`pose_00_near_native`, RMSD `0.3002` Å, Met793 N distance
  `2.6624` Å, `0` clashes) scores `-15.961` (`-12.88` vdW-only).
- **Cross-docking receptor-conformation penalty**: placing `4HJO` (`AQ4` from an
  inactive-like EGFR state) into rigid `1M17` flips the score to `+11.8116` (`5`
  steric clashes `< 2.4` Å, minimum Met793 distance `1.8836` Å), while placing
  DFG-out `1XKK` (`FMM` / lapatinib) into rigid `1M17` produces `+261.2519` (`31`
  steric clashes `< 2.4` Å, Met793 distance `4.1362` Å).
- **Decoy enrichment (`16` candidates: `4` active hinge-binding poses vs `12`
  translated/rotated decoys)**: vdW + H-bond achieves `ROC-AUC = 1.0` and
  `EF_25% = 4.0` (`4 / 4` top hits).

## Independent exercise

A slide compares two series: "series A docks at -9.4, series B at -7.1. We are
progressing A." The methods section says the two series were docked at different
times by different people using the same program.

Say what you would need to establish before the comparison means anything, and
what you would do if that information no longer exists.

<details data-worked-answer>
<summary>Worked answer: separate score definition, search and validation</summary>

The program name does not establish a matched protocol. Recover the receptor
state, ligand and protonation preparation, box, scoring and rescoring functions,
constraints, search effort and random seed. A different scoring function can
change the numerical scale. A different search effort can change which pose is
found while leaving that scoring function and its units unchanged. The
[AutoDock Vina FAQ](https://autodock-vina.readthedocs.io/en/latest/faq.html)
makes this distinction in its description of exhaustiveness and search.

Nothing in the slide establishes which settings differed or whether either run
was validated. Check those records. Reference-pose recovery tests pose placement;
a ranking claim also needs an appropriate known-active comparison under the same
declared protocol. Neither check alone establishes binding affinity or activity.

If the records are missing, the reported -9.4 and -7.1 do not support a controlled
comparison of the series. A new matched computation can address that missing
comparison, with its own input record and validation. It remains a new
calculation, not a reconstruction of the missing run. If that work is unavailable,
base the progression decision on other suitable evidence and leave the docking
comparison unresolved.

</details>

## What this does not do

It runs no docking program, prepares no structure, and does not establish that any
score is correct. It reads declarations and reports which comparisons the
declarations permit.

**A reported docking score is the best number a particular search found under a
particular scoring function with particular constraints.** It is not a binding
free energy, not a prediction of activity, and not comparable to a number produced
by a different protocol.
